# CLAUDE.md

Guidance for AI coding assistants working in this repository. Humans: see `CONTRIBUTING.md`.

## What this is

Sheltr is an offline-first disaster-preparedness guide. No server runs in production. A TypeScript publisher (`tools/publisher`, Node) builds an Ed25519-signed bundle of approved official documents. The app (`apps/mobile`, Expo / React Native / TypeScript) verifies it, stores it in SQLite FTS5, and answers by keyword retrieval with citations. Design: `docs/adr/0015-offline-mobile-publisher-no-server.md`, `docs/design/offline-mobile-app.md`.

## Layout

- `tools/publisher`: Node and TypeScript CLI (manifest, fetch, extract, chunk, sign). Node 24 runs the `.ts` files directly; use only erasable TypeScript syntax (no enums or parameter properties) and `.ts` import extensions.
- `apps/mobile`: Expo app for Android and iOS. `src/core` is framework-free TypeScript (bundle, signature check, store, retrieval, sync, settings); `src/app` the screens; `src/platform` the Expo glue.
- `corpus/manifest.yaml`: the approved corpus.

## Commands

```bash
cd tools/publisher && npm run typecheck && npm test               # Node 24
cd apps/mobile && npm run typecheck && npm test                   # Node 24
```

Install Expo packages with `npx expo install <pkg>` (SDK-compatible versions), and use `--legacy-peer-deps`. Never commit `apps/mobile/android` or `ios`: they are generated by `npx expo prebuild`.

## Rules

- Safety first: answer only from approved documents, always cite, refuse when no source passes the relevance check. Never add invented guidance.
- Never read, create or commit a signing key inside the repository. `RepoGuard` enforces this for the publisher.
- No network calls from the apps except fetching the signed bundle over HTTPS. No analytics, no accounts.
- Verify signatures before trusting any bundle content. Treat fetched documents as untrusted input.
- Keep changes focused, add tests, and do not claim tests passed unless they were run.
- Corpus changes need licence, attribution and checksum in the manifest; update `THIRD_PARTY_CONTENT.md`.
- Significant decisions get an ADR in `docs/adr`.
