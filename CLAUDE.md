# CLAUDE.md

Guidance for AI coding assistants working in this repository. Humans: see `CONTRIBUTING.md`.

## What this is

Sheltr is an offline-first disaster-preparedness guide. No server runs in production. A TypeScript publisher (`tools/publisher`, Node) builds an Ed25519-signed bundle of approved official documents. The app (`apps/flutter`, Flutter / Dart) verifies it, stores it in SQLite FTS5, and answers by keyword retrieval with citations. `apps/mobile` (Expo / React Native / TypeScript) remains the oracle until `docs/release-checklist.md` is done. Design: `docs/adr/0015-offline-mobile-publisher-no-server.md`, `docs/design/offline-mobile-app.md`.

## Layout

- `tools/publisher`: Node and TypeScript CLI (manifest, fetch, extract, chunk, sign). Node 24 runs the `.ts` files directly; use only erasable TypeScript syntax (no enums or parameter properties) and `.ts` import extensions.
- `apps/flutter`: Flutter app for Android and iOS. `packages/sheltr_core` is framework-free Dart (bundle, signature check, store, retrieval, sync, settings, passage rewriter); `lib` is the screens, localisation, and background scheduling.
- `apps/mobile`: Expo oracle. It stays until the release checklist is done. Do not delete it in that checklist commit.
- `corpus/manifest.yaml`: the approved corpus.
- `contract/`: bundle fixtures and `check-coverage.mjs`.

## Commands

```bash
cd tools/publisher && npm run typecheck && npm test                 # Node 24
cd apps/flutter/packages/sheltr_core && dart test
cd apps/flutter && flutter test
node contract/check-coverage.mjs
cd apps/mobile && npm run typecheck && npm test                     # Expo oracle, Node 24
```

Flutter/Dart is not assumed to be on PATH. Install Expo packages with `npx expo install <pkg>` (SDK-compatible versions), and use `--legacy-peer-deps`. Never commit `apps/mobile/android` or `ios`: they are generated by `npx expo prebuild`. Do not turn `AppSettings.modelEnabled` on.

## Rules

- Safety first: answer only from approved documents, always cite, refuse when no source passes the relevance check. Never add invented guidance.
- Never read, create or commit a signing key inside the repository. `RepoGuard` enforces this for the publisher.
- No network calls from the apps except fetching the signed bundle over HTTPS. No analytics, no accounts.
- Verify signatures before trusting any bundle content. Treat fetched documents as untrusted input.
- Keep changes focused, add tests, and do not claim tests passed unless they were run.
- Corpus changes need licence, attribution and checksum in the manifest; update `THIRD_PARTY_CONTENT.md`.
- Significant decisions get an ADR in `docs/adr`.
